# Preserve source cell content flow

Source Intake retains a cell's ordered controls, explicit `BR` / `brcontrol` boundaries, and explicit item widths as `contentFlow`. Transparent presentation wrappers preserve those boundaries; an atomic control, script, JSP fragment, or nested table owns its internal markup. Empty lines represent explicit consecutive or edge breaks. Widths use finite, non-negative `px` or `%` values, including deliberate zero-width source controls.

The Source Draft and DSL cell shape is:

```json
{
  "contentFlow": {
    "lines": [["fd_start", "fd_end"], [], ["fd_note"]],
    "items": [
      { "referenceId": "fd_start", "width": { "value": 160, "unit": "px" } },
      { "referenceId": "fd_end", "width": { "value": 40, "unit": "%" } },
      { "referenceId": "fd_note" }
    ]
  }
}
```

Each executable field-cell reference occurs exactly once, in order, in both `lines` and `items`. Multi-reference field cells retain `keepInline: true` for grid membership; `contentFlow` governs their internal arrangement. Detail tables retain their exclusive-cell projection. The mapper remaps content references together with field IDs. A merged address display companion contributes its position and width to the surviving address control.

Source unit labels remain source entities with their original identities. The mapper consumes a unit label only when the chosen target component supports a matching native unit. Otherwise it retains a description control. Calculated fields keep their distinct native calculation profile; ordinary number formatting is not a substitute for that profile. Hidden titles use the shared native fieldset contract across visible components.

The Executor projects flow through XForm's built-in `div` containers with explicit CSS flex styles. Generic `@elem/flex` and `@elem/flex.FlexItem` components are not registered as XForm containers: its renderer silently skips their subtrees. Explicit lines remain distinct, items retain their widths with a 100% maximum, and each line can wrap at the available width. This adds no internal table borders. The native registration and rendering methods are retained with bundle provenance in `tests/fixtures/executor/persistence/form-renderer-registration.json`; tests replay that traversal from source XML through persisted field references on desktop and mobile. Field label evidence remains in `hidden-label-runtime/provenance.json`.

Trust checks compare source line boundaries, item dimensions, hidden titles and unit text with the DSL. A source rebuild authorizes existing data-only and address-companion transformations, consumed native units, and source-proven one-to-one caption folding. Caption folding retains the original source grid, verifies the complete field semantics and combined occupied region, and requires the intrinsic title to remain visible. The remaining presentation expectations come directly from source facts. Readback derives flow and effective native titles from the actual hierarchy and rendering properties on both desktop and mobile, independently of migration audit markers.

New DSLs explicitly select `form.layout.sizing = "adaptive"`. Source dimensions remain unchanged in `sourceGrid` and `contentFlow`; the target projection uses automatic grid tracks and stretchable visible editors. Descriptions and units keep intrinsic sizing, and explicit zero widths remain zero. Line boundaries, topology, field identities and behavior do not change. A missing sizing flag retains the original native width policy; mapping with `layoutSizing: "source"` is the explicit compatibility path.

Adaptive title styling is fixed executor infrastructure: a built-in `div` carries a fixed `<style>` element through its native DOM props and provides a unique marker for the created main table. An unbound HTML control cannot carry this infrastructure: the native designer serializes controls as field UUID references and loses their inline configuration. The built-in container retains its props across native save and reassembly without adding business fields. Native `appearance` and `main` do not forward a usable DOM scope. The marker precedes `main` as its sibling under `appearance`; general-sibling selectors scope the following form content. Keeping `main` directly below `appearance` preserves the designer's native `.ele-xform-appearance > .receiver` selectors, including detail-table flex layout. Only main-field flow items receive the fixed `mk-adaptive-main-field` class: title rules must not reach native detail headers, whose fixed-height designer styling cannot accept main-field wrapping. Both main title layers override fixed native widths; only a horizontal field's direct title wrapper receives the relative 50% cap, allowing long titles to wrap without constraining nested vertical fields. Readback checks each platform's actual marker/carrier, sibling order, main-field classes, exact CSS-only content, reachability and automatic grid/item styles. Source HTML/CSS and model-supplied markup never enter this carrier.

Text-label presentation is a separate source contract. Intake records explicit label font size in pixels and text alignment from the label or its owning table cell, including unquoted legacy `align` attributes. Label CSS takes precedence over cell CSS/attributes. DSL description style exposes only typed `fontSize` and `textAlign` additions; arbitrary source CSS remains inert. Both native platforms retain the font size and alignment, with mobile `alignDesc` and the description content style verified independently. Source trust rejects lost or changed facts. A proven one-to-one caption still folds into its intrinsic field title; these two presentation properties move to the typed main-field `titleStyle`, independently checked in both platforms' label styles. This preserves source presentation without resurrecting a duplicate label or changing field values, permissions, or calculations.

Offline route tests cover both sizing policies, mixed controls, empty breaks, physical and percentage source evidence, identity changes, units, merged address controls, and corrupted source-to-DSL or native presentation. Executing retained renderer code verifies registration and stylesheet mounting. The manual browser evidence described in `../operations/adaptive-layout.md` covers computed CSS in an isolated native-DOM fixture. It does not establish server normalization or full interactive application acceptance; those require separately authorized test-draft execution and runtime verification. Existing draft recovery and published repair scopes do not gain permission to change layouts.

Source-proven same-line Other companions retain their separate business fields, option codes, permissions, values and scripts. Both prefix and suffix companion titles are recognized using same-cell source evidence. When the original Other code is the last native choice, a fixed scoped stylesheet reserves the original textbox's space inside that option's inline box; the following original textbox consumes the reservation without DOM reparenting or value mirroring. Native row boundaries are retained on desktop and mobile, and the pair wraps together. A separate Other caption/toggle and textbox use one non-wrapping container. Explicit source breaks, unrelated text, ambiguous companions and zero widths do not acquire this presentation. A compound textbox's source width is an upper bound, capped at half the available line for an embedded tail companion. The source dimensions remain unchanged in DSL evidence.

Compound layout is executor infrastructure derived from DSL relationships, using registered `div` containers and the same persistent CSS-only container transport. Readback verifies the actual grouping, roles, scoped CSS, carrier visibility and widths on both platforms; it cannot accept the old detached layout merely because field references and audit markers survived. The native inline-tail stylesheet requires CSS `:has` and `display: contents`. Offline replay fixtures retain the current native desktop/mobile checkbox/radio modules and styles with GET provenance. These tests do not access NewOA or execute migrated scripts.

Run `node --test tests/route-validation/choice-other-wrap.test.js` for source, trust, persistence and readback counterexamples. Enable the computed-layout matrix with `MK_LAYOUT_BROWSER_TESTS=1` on the same command. It requires Playwright and an installed Chromium browser; `MK_LAYOUT_PLAYWRIGHT_MODULE` may name the Playwright module entry point and `MK_LAYOUT_BROWSER_PATH` the browser executable. The matrix measures overlap, horizontal distance, wrapping and usable textbox width for checkbox/radio, H/V alignment, adaptive/source sizing and desktop/mobile at 900, 550, 400, 320, 240 and 180 pixels. React effects, external services and core input adapters are inert; this is offline native component/layout evidence, not acceptance of a deployed NewOA form.
