# Source field captions and native titles

Fresh Source Drafts carry `form.captionRelations`. Source Intake establishes
ownership from the original literal binding, occupied cells, actual rendered
editor and permission wrapper. A false `_label_bind` flag alone is not a reason
to reject a relation. An inactive stale pointer outside the rendered value cell
is not a second rendered owner; competing active claims and compound bodies
remain protected. These are target-neutral source facts.

Candidate inventory includes raw visible `_label_bind_id` relations even when
the old layout caption marker is absent. A single adjacent description whose
text is the control's title is the rendered caption when the exported bind is
not active. A caption that remains a separate control is not also shown as that
control's native title. Existing source column-header roles
remain authoritative: a decorative specification column must not become the
next quantity editor's title because of a stale designer pointer. Calculation
editors use the source export's `xform:xtext` renderer; their formula and readonly
value semantics still belong to the original business field.

The semantic mapper consumes `field-caption` relations by default. One source
caption and one input become one target field with a visible native title. The
standalone description and its occupied cell are removed; the field cell takes
the union of the two spans. The original Source grid is retained as evidence.
Field identity, options, required/readonly/default semantics and workflow
condition resolution use the original business field identity. The DSL retains
`sourceProps.foldedCaption.referenceMap` to distinguish the former label's title
identity from the field's value identity and the source row region. Shortened
field IDs also update the target side of this map.

A proven title cell may contain one terminal empty content-flow line after its
single title item (for example, an exporter `brcontrol` placeholder after the
label). This is recorded as `captionTrailingEmptyLine` in the source relation;
the original grid and hidden data companions remain unchanged. It does not
authorize leading blanks, multiple blank lines, editor-cell tails, additional
visible controls or independent permission/script effects. Retained source
artifacts without this relation keep their previous projection.

Source normalization also accepts a single terminal BR plus whitespace entities
only when the literal caption has the matching terminal newline. A rowspan in
another column does not block a title when a bounded physical occupancy check
agrees with the explicit source/runtime columns; overlapping, malformed or
unknown geometry remains protected. Literal default table layout metadata must
use known values, and its outer/FD mirrors must agree. None of these rules changes
the original source grid, rich typography or independent caption behavior.

A common permission wrapper is retained on both source entities, including
wrappers outside the row fragment. Its title can join the field only when the
permissions agree. Independent wrappers or differing node visibility/modes stay
separate. Redundant presentation-only authority entries may disappear only with
the consumed label; the surviving field's permissions and all workflow business
conditions remain unchanged. Shared/group titles, rich captions, independent
label events, data-bearing labels and unproven regions are retained with evidence.
Bold, italic and underline on the label itself are title emphasis. They become
the field's native title and are recorded as `titleEmphasis`; color, font
family, effects and ancestor formatting stay unfinished. An unknown rendering
relation is not a completed exception merely because the mapper cannot yet
handle it.

## Behavior mapping

The normal script translator first maps against the semantic form. Caption
mapping reuses its closed deterministic proofs and complete source statement
ranges. It only consumes complete AST statements (including an optional inert
semicolon); runtime whitespace/line-ending differences do not create a new
program. The target operations must use the bounded field-value/attribute API
contract. No source script is executed, removed from Source Draft, or dropped
from the final script migration path by this coverage check.

Complete source-row operations stay region operations and are recompiled against
the surviving target fields. Field-only visibility changes retain the independent
title because hiding an editor and hiding its entire native wrapper differ.
Direct label references/events are protected until a native title-specific
operation is supported. Value operations keep addressing the business field.

Remaining scripts use the existing bounded impact proof, without extending its
JavaScript language. A local, fixed effect protects its exact field/caption or
ancestor region. When that proof stops, reach is a separate boundary: DOM
operations anchored to a closed set of literal ids, rows or non-title selectors
block only those nodes. Reading or writing a field value, including
`GetXFormFieldById(id)[0].value` and a jQuery `.val()` / `.prop("checked")`
on that field, stays a data operation. A guarded `for...in window` whose key
must start with a non-field prefix such as `attachmentObject_` is that prefix,
not a form-wide walk. An unknown call that receives only closed nodes protects those nodes; a call
with no node, a dynamic selector, a prototype write,
eval, wide DOM collection or unresolved row still has no pair boundary and
blocks every candidate. Reports retain the first reason, script index/offset,
source excerpt and `impact` boundary. Unknown code is never treated as an empty
program. A concrete field id outside the export is recorded and does not discard
the rest of a completed target set. Prior Source Drafts without the relationship
inventory keep their earlier compatibility path.

A no-argument native submit callback may contain an unused local button-text
scratch variable: a single `var` declaration reading `window.event.target.innerText`
and a later `if (!name)` fallback assigning `window.event.target.value`. Only
those three identifier occurrences are allowed in the complete callback body.
Caption impact analysis records and skips these unused scalar reads; source and
migrated validation scripts remain unchanged. A later read, capture, redeclaration,
extra fallback effect or any other event-target use retains the opaque boundary.

Closed mapped coverage is also usable for a literal native toast and proven
detail value updates. Detail item visibility retains its exact table/column
presentation boundary. Unknown APIs, dynamic target identities and stale proofs
do not acquire coverage. An earlier direct function declaration may be ignored
only when the final same-name declaration in that same Program is fully covered;
this rule never selects a winner across SCRIPT boundaries.

Static literal member spelling, including `Com_Parameter.event["submit"]`, uses
the same submit entry contract as dot access. Dynamic keys, other registries,
registry mutation and unknown callback effects stay opaque. A node collection
may appear in a boolean predicate; it does not become scalar data. Both operands
and both branches are checked. Source-defined `getFormFieldValue` helpers are
analyzed through their actual bodies. Only direct same-Program declarations use
their final body; different SCRIPT programs retain every possible definition.

The complete existing active-attachment guard recognizer can establish a data
read of one uniquely typed attachment. Missing/duplicate source identity, native
binding shadowing, extra effects and incomplete guards do not acquire coverage.
No general loop or attachment-handle exemption is introduced.

Complete mapped select updates may set only `options` on one known select.
Complete mapped detail replacements require one exact detail-table reference
and protect that entire table and its columns. Validation toasts may concatenate
literal text with a local, unaliased array of numeric row positions. External
arrays/values, escaping arrays, unknown counter mutations and arbitrary message
builders remain unproven. These checks reuse complete current deterministic
source coverage; no source or migrated action is removed or rewritten.

Source-owned primitive `var` bindings shared by callbacks are widened to an
unknown scalar. All branches still contribute their effects; neither declaration
order nor a visited assignment selects a current value or target identity.
Ownership is rebuilt from the complete current source inventory even when a
mapped statement consumes a declaration. Host bindings, implicit globals,
nonliteral/object state, node-handle escapes and ambiguous local shadows do not
use this rule. This is an impact proof, not a shared-state execution rewrite.

A covered helper declaration remains in impact analysis when an uncovered
callback still references it. Dependencies are retained transitively across the
complete program inventory, and the normal checker analyzes their actual
bodies. No call result or side effect is invented from a coverage label.
An omitted helper parameter is the known primitive `undefined`; the internal
unproven return/union sentinel remains distinct and cannot enter scalar APIs.

Source row impact can cover the union of all complete same-name rows without
choosing a canonical execution target. Audited orphan no-ops are rebuilt from
current source semantics and literal reset evidence; a missing target alone is
insufficient, and the complete runtime still has to pass impact analysis. This
does not change executor row resolution or any write/repair gate.

An exact native currency include may use the existing currency value contract
only when every currency control has matching amount identity, numeric/text
types and literal readonly runtime binding evidence. This is impact evidence,
not a library filename whitelist or a new migrated script action.

Program inventory and rendering ownership are separate. A complete lexical
inventory can retain uninterpreted permission/table metadata duplicates in known
literal domains while still collecting every handler. Ownership parsing remains
strict inside the ambiguous region; no permission or table value is chosen.
Executable duplicates, dynamic metadata and malformed attributes remain opaque.

Agent Review sees the ownership inventory and the consumed label reference map,
including in compact reviews. Review cannot recreate a label or change a visible
title's business field identity; trust independently rebuilds the expected DSL.

## Model-assisted judgment

A model can review the source relation, complete program inventory and explicit
remaining dependency gaps, then propose a source-backed relation or a reusable
proof rule with counterexamples. Its report should distinguish missing evidence,
unimplemented proof and an independently observed presentation effect. Source
references, offsets and artifact hashes make the proposal reviewable; model
confidence is not a substitute for that evidence.

The current Agent Review replacement contract cannot delete a label, create a
caption relation, or override an unbounded impact result. Such a proposal first
needs a local common rule, a source fixture and positive/negative route tests.
Keep model review separate from deterministic translation and target execution.
No provider call is part of the offline caption verifier.

## Source-backed data impact

The impact checker recognizes the complete source form-value reader by AST and
binding structure, including selected option text and the SDK fallback. It
returns abstract data, never its internal DOM handles. A source-owned immutable
lookup domain may bound this data reader or a complete guarded detail-value
aggregate; it does not make that initializer the current shared value or permit
an arbitrary dynamic selector, node lookup or event registration. Writes in a
different function's hoisted local scope do not mutate the Program binding.

Shared JSON impact is rebuilt from the existing complete source state model.
Only exact AST fragments at their source offsets can use its data-read/write
proof. Residual DOM effects remain visible. A finite forward traversal of an
unchanged primitive split result visits the body with an abstract index and
joins the zero-iteration state; it never supplies a concrete field identity.
Private Date setters and numeric formatting stay data operations. A free
identifier under `typeof` has an unknown type; both branches still need proof.

Complete detail sum and filtered aggregate contracts require a registered typed
table, unique value/radio columns, the actual pure rounding dependency and typed
value outputs/counter. Their complete source algorithms, guards, return values
and effects must match. Extra effects, changed loop bounds, caption outputs and
mutable lookup domains stay opaque. A fixed table polling helper likewise needs
its complete AST, stable self binding and registered table; its entire table is
protected. The source's omitted timer argument is preserved, never repaired.

A helper-only designer unit can be a non-entry library only under its existing
exclusive non-executable omission contract and independently verified declaration
grammar. The checker still proves every active caller and rejects escaping bare
function references. This does not waive unbound functions in raw display JSP.
The native scalar currency converter uses the existing complete typed readonly
currency binding; source overrides, node arguments and unknown includes fail.

These contracts only add impact evidence. Source and migrated scripts are not
rewritten or executed. Passing a sub-proof is not a completed caption relation.
In particular, main-name radio `.parent().remove()`, global comma selectors for
generated row images, global prototype consumers and external REST/Dialog
callbacks still need complete ownership/effect evidence and implementation.
An existing approved omission policy is not evidence of source equivalence.

## Independent offline acceptance

```sh
node scripts/verify-caption-folding.mjs manifest.json new-output-directory reviewed-expectations.json
```

The manifest names the fixed input exports. The separately reviewed ledger has
`forms: [{id, inputs: [{path, sha256}], relations: [{fieldId, sourceRef,
captionIds, title, expectation, basis, evidence}]}]`; expectations are `merge`,
`exception` or `needs-evidence`. The verifier never derives these expectations
from its merger. The ledger must cover the complete candidate inventory and its
original XML hashes. Keep authored/reviewed ledgers and historical reports
immutable; save a new revision for an evidence-backed correction.

Each required merge checks one target field, no old description, one native data
model control, one reachable desktop/mobile control and a visible matching title.
The retained upstream NewOA fieldset module is replayed offline with inert leaf
editors to verify title rendering on both scenes. This does not prove browser
CSS, online persistence or business behavior. Source/user JavaScript is never
executed in this replay.

The safety comparison independently preserves field properties, scripts, rules,
workflow, source grid and every target cell outside the specified joined regions.
It does not weaken execution or trust gates. Only synthetic form configuration
and fake clients are used; network sockets and fetch are blocked, and no model,
batch store or NewOA write is invoked. Output directories must be new.

Reports separate `configurationSafe` from `captionGoal`. Without a reviewed
ledger the goal is `not-assessed`. Missing required merges and `needs-evidence`
relations make the goal `incomplete` even if every configuration check passes.
Exit code 0 means the requested checks passed (goal complete when assessed), 1
means a safety/expectation failure, and 2 means the assessed title goal is still
incomplete. Zero merges therefore cannot pass a nonempty required-merge ledger.
