# 自适应表单布局

新生成的 DSL 使用 `form.layout.sizing: "adaptive"`。正常新建草稿的原生投影会：

- 为桌面、移动端的表单布局列明确设置 `colsStyle[].value = "auto"`。
- 让可见编辑控件的外层以 `flex: 1 1 0; width: auto; min-width: 0` 伸缩。
- 让描述、单位、按钮等保留内容宽度，保留显式换行和零宽伴随控件。
- 保留字段身份、类型、必填、默认值、只读权限、事件、行列顺序与合并关系。
- 保留 Source Grid、宽度权重与原 `contentFlow` 尺寸作为来源证据。

没有 `sizing` 标记的旧 DSL 继续走原有宽度策略。程序化映射可用
`draftSourceDraft(source, { layoutSizing: "source" })` 明确生成兼容模式；
不会自动改写已有 DSL、模板、执行报告或锁。

## 原生标题样式

当前 QAS fieldset 在横向布局下仍生成桌面 `8em`、移动端 `6em`，
普通 `labelStyle.width = "auto"` 会被覆盖。固定的 CSS 片段同时处理
`.ele-xform-fieldset-label` 及它的直接文字 `span`，使用 `width: auto !important`
和 `max-width: none !important`，允许长标题换行。

横向字段的直接标题包装允许收缩，并最多占其可用宽度的一半，以保留输入空间。
这里的相对上限不是标题固定宽度；短标题按内容占位。规则使用直接子级选择器，
不将该上限错误施加给横向复合控件内的纵向标题。

样式由原生 `@elem/xform-html` 控件的 `source.css` 承载，`html` 和
`javascript` 均为空，不增加业务 `fdFields`。一个真实的内置 `div` 包装
`main` 和样式控件，使用目标主表名摘要生成唯一作用域。每条样式规则均限定
在这个作用域内，不改变全站样式。

回读会核验双端作用域、唯一载体、空 HTML/JavaScript、完整固定 CSS、
可渲染节点结构，以及自动列宽、编辑器／描述外层和内容顺序。
载体隐藏、删除、重绑定、注入额外脚本或宽度退回固定值都会失败。

## 明细表内部列宽边界

上述自动列宽针对表单布局 Grid。明细表自身的 `columnWidth/columnSetting`
是另一条原生配置路径；当前设计器会把 `"auto"` 拼接为 `autopx`，
运行时未配置又默认回到 142px。不能把删掉宽度参数称为明细表自动列宽。
本次保留该组件原有配置及单独审批的建议列宽，不写入未经证明的 `auto`。
明细表所在的布局列、外层区域与标题仍采用本次自适应规则。
