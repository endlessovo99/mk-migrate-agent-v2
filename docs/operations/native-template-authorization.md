# Native template reader authorization

The public DSL carries source access intent. Native `fdAllReaders` is a derived collection; assigning it does not establish the formal reader range. This behavior is evidenced for the exact native module release and content digest in `src/executor/template-read-scope.js`, together with the captured route-validation fixture. Backend implementation source is unavailable; the contract is limited to the observed native behavior.

For an explicit nonempty range, keep formal readers even when they also resolve to editors. The expected effective collection is the reader/editor union. An empty formal range without source-bound public evidence is rejected before execution; it must not create a public draft and wait for readback failure.

A source everyone range requires paired form/process/companion template identities, original companion XML hash, a unique `authAllReaders` Person with exact login `everyone`, the original empty/absent formal readers, `authReaderFlag=true`, and the normalized authorization hash. Ambiguous, duplicate, mixed or incomplete evidence is rejected. The translator binds this fact to `template.authorization.readScope`; source trust and review retain it.

The executor verifies the native module release/content, `business.templateEmptyNotUse`, and the unique target builtin account before any template write. Only absent configuration or the string `false` is currently supported for the observed empty-public behavior. String `true`, malformed values and unknown module versions are blocked. Use the existing `templateAuthorizationOverrides` mapping when builtin discovery cannot return a unique candidate. Mapping alone is insufficient: exact lookup must prove Person type, availability, nonbusiness classification, and nested account login `everyone`. No tenant UUID or template name is hardcoded.

Ordinary Person targets must establish business-account classification. Direct mappings and temporary fallbacks request the builtin evidence columns; a search result missing classification is independently checked by exact lookup. Missing metadata, conflicting top-level/nested logins and builtin accounts are blocking errors, including when fallbacks are enabled. A builtin cannot stand in for a missing person or become an ordinary workflow approver.

For proven public mode, native persistence sends formal `fdReaders=[]`, preserves formal editors, and omits the writable root `fdAllReaders` assignment. Readback expects the exact verified builtin effective reader identity. Module/configuration/identity evidence is checked again before the transfer-record callback. Drift or any permission mismatch withholds the record. The fake client derives collections from formal inputs and configuration rather than echoing the requested aggregate.

Existing prepared items require the normal engine-change repair/reprepare and new approval digest. This support does not authorize existing-target changes. The obsolete `formal-editor-readers-only` recovery profile is rejected before I/O because its aggregate-only write cannot restore native access intent. Existing locks, claims, execution reports and migration records remain immutable. Successful historical items and permanently isolated targets cannot be rerun, recreated, or recovered merely by selecting a new profile, digest, batch or artifact directory. Any further recovery must have its own reviewed scope under the repository's existing-target policy.

## Explicitly authorized existing-draft closeout

The separate `authorization_closeout` repair action supports `mode: "finalize_record"` and `mode: "repair_readers"`. Use the existing `createScopedRepair` / `previewScopedRepair` / `applyScopedRepair` persistence path with explicit selected item IDs; do not reset items or rerun ordinary migration. This exception requires its own human authorization covering the named existing targets.

`prepareAuthorizationCloseoutReplacement` rebuilds the frozen source, rebinds the same already-authorized migration policies to the new source fact digest, and invokes ordinary model review, trust and dry-run. Its successful result is a replacement row with the old `expectedDslDigest`, old `expectedSourceDigest`, fresh `sourceDraft`, `dsl`, and current engine digest. Add the independently validated `everyoneTargetFdId` to the private replacement row (or pass it to the preview API). No business policy decision or target identity is inferred from a template name.

Preview requires a paused serial batch, retained original source bytes and execution report, and stable target snapshots. The complete replacement, historical evidence, resolution options, native projection, target snapshot, repair definition and engine enter a new approval digest. Confirmation repeats the checks. Existing normal repair actions retain their previous eligibility and cannot reach this exception implicitly.

For `repair_readers`, the original item must already have a successful, matching transfer record. The request changes only root and bound-workflow formal readers; it omits only the derived effective readers and transports the exact unchanged full workflow content. The draft API replaces its binding; omission clears `fdContent`. The native existing-basic-info route that omits content sets `isDraft:false`, so its omission behavior cannot be applied to `isDraft:true` recovery. This rule is based on the acknowledged draft update and independent API readback, not an assumed backend implementation. There is exactly one template update, no workflow save, and no transfer-record call. Postwrite comparison permits only native-derived effective readers, nondecreasing timestamps on the exact root/XForm/main-model identities, and exact typed editor references with omitted display names. All other raw state and all five semantic partitions remain protected.

For `finalize_record`, the original target claim must retain a known acknowledged authorization update with no uncertain native write and no started record callback. Its original permanent lock must still match its private state, and its retained after snapshot must still match the live target. Only a new `authorizationCloseout` stage is appended to that same claim. The old claim fields, old failed result, old permanent lock and prior attempts remain retained; no template/workflow write is allowed. Exactly one transfer-record request follows full stable verification.

Both operations create a deterministic, immutable closeout-phase intent in the existing user's migration lock area and retain private before/payload/receipt/after/result artifacts. A new artifact directory or digest cannot replay the phase. The existing batch target document protects concurrent closeout operations; batches at that origin must remain paused and each target operation runs serially. On success, append a closeout attempt to the original item and retain its identity, original snapshots, previous attempts and records. On unknown outcome, quarantine that phase and do not repeat it. The new phase does not rewrite an old permanent lock.

Closeout source comparison permits only additive version-1 parser proofs in the named main-string binding and shared-JSON/runtime/radio source-domain fields. Existing proof values and all business source facts still compare exactly. Preview independently rebuilds the entire current Source Draft from the frozen XML and unchanged authorized business policies; arbitrary replacement proof metadata is rejected. The source proof additions and new scope remain bound to the fresh full Source/DSL and preview digests.

If ordinary review rejects a newly generated script translation, `prepareAuthorizationCloseoutReplacement(..., {retainScriptCandidates:true})` may seed the exact implementation from the original retained execution as a candidate. It verifies source/action/provenance and executed-artifact identity, applies the normal source-evidence patch validator, and leaves the action `needs_review`. Seeding is explicitly audited as having no provider review; a new real provider review is still required. An unchanged authenticated review checkpoint can resume only through the normal checkpoint mechanism.

Existing presentation choices are preserved as draft candidates before review: titles bind to the unchanged original source identity and executed artifact, remain subject to the normal patch validator and real provider verdict, and cannot drift during a permission-only closeout. This does not claim that an earlier chosen caption is a literal XML label. Inactive existing ordinary editors may be retained with exact business/type/name evidence and an explicitly bound availability state; this path neither activates them nor selects them as new fallback accounts. The native everyone identity must still be available.

Legacy recovery reports may omit a false outcome flag. Omission alone is never proof: record finalization additionally requires the matching unchanged permanent/private states with explicit completed/known template-write and never-started/known record flags, one acknowledged update stage, no workflow/create/record write stage, and no contradictory native-write journal intent. Any affirmative uncertainty remains blocking.


`mode: "restore_graph"` is a separate explicit exception, not an automatic rollback. It accepts only a prior known-acknowledged `repair_readers` phase with an omitted graph in its retained request, an intact exact before backup, and a missing graph in the saved/live after snapshot. The caller must bind the named target/category/workflow/claim, exact graph hash, failed-result hash and current snapshot hash to explicit human authorization. The original phase, receipts and permanent locks remain immutable; one `graphRestoration` stage is appended in the same claim. Its template update transports the current state with only the missing graph restored; no reader delta, workflow publish/save, migration record or replacement target is allowed. Two stable complete readbacks and exact graph/protected-state comparison are mandatory. A deterministic restoration lock prevents any retry, including from another artifacts directory.

For an existing ordinary editor, source-bound singleton collections and a retained successful report containing the identical source/target ID may supply a retained mapping. This is recorded as `retained-singleton-same-id`, then validated by the normal exact typed lookup and independently checked against current editors. It does not infer multi-member correspondences or replace conflicting mappings. An unavailable retained editor is preserved unchanged, without enabling it. Diagnostic selectors also apply to closeout previews before native calls.


An acknowledged native draft update also initialized detail-model audit metadata. Exact unchanged detail model ID/table/schema pairs may normalize only (a) a previously absent `fdAlter` equal to the unchanged current root actor, (b) an absent `fdDeletedFields` becoming `[]`, and (c) a valid nondecreasing `fdAlterTime` in the current root-to-XForm update interval. Field/schema/deletion history, model identity, actor replacement, invalid/backward/out-of-interval times and other audit paths remain blocking. The fixture and counterexamples bind this behavior to the actual retained before/after request evidence; no business data delta is allowed.

Before closeout, the executor verifies one workflow binding and independently validates both the template-bound workflow and the detail response against the complete DSL. A valid detail response must not mask a missing/foreign bound graph, lifecycle, or authorization. Ordinary draft updates must still carry the exact unchanged graph; only the explicitly granted restoration mode accepts an absent/null/empty graph, never arbitrary falsy values.

All retained attempts and native intents are checked before every mode, including graph restoration. A false summary does not override an affirmative template/record/step uncertainty. The executor also reads the deterministic historical lock itself: a caller-selected private copy is insufficient for record finalization, and permission repair/restoration cannot bypass an uncertain or incomplete canonical history lock. These checks never modify old locks.

Exact restoration recomputes the full original approval-bindings digest and matches its original DSL, Source, prior Source/DSL/report, execution options, target and category to the current retained phase. Both journal intents must equal the acknowledged request. A matching digest label or self-consistent foreign artifact is insufficient. This is in addition to the exact graph/current-snapshot/result grant, two stable reads, immutable claim/phase locks and complete protected-state verification.


The closeout claim locks the shared origin target row before batch/item rows, rejects running workers even when a batch was paused, and rejects other applying repair runs. Ordinary batch resume, execute claims, concurrency-limit changes and older scoped-repair entry points all honor the same active closeout marker. They cannot start another write while a closeout awaits its native receipt/readback; the marker is cleared only by normal retained-phase finalization. No second scheduler or target lock namespace is introduced.
