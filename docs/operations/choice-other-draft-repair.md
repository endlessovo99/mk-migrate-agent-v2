# Source-bound checkbox Other draft update

`repairChoiceOther` is a separate scoped operation for a successful, registered,
still-draft `MK_TEST_` template. The caller must explicitly authorize updating
the affected existing templates and bind that authorization to the exact origin,
category, source IDs and target IDs. A request to translate, preview, or create
new templates does not authorize this operation.

The input remains Source Draft plus trusted DSL. The operation retains the
previous successful execution report, source and DSL, validates the new trusted
DSL, and binds both complete artifact sets, the current engine, the scope and
two stable native snapshots to a preview digest. It never uses a process ID
specific migration rule.

The allowlisted change converts a source-backed independent Other description
into an ordinary checkbox on the same field identity and appends the compatible
initialization helper to the existing singleton onLoad dispatcher. The original
choice and explanation fields, values, options, defaults, scripts and permissions
stay protected. The new checkbox uses the intersection of their permissions.
Only the corresponding intrinsic wrapper widths and checkbox style are updated.

Apply requires explicit write confirmation and the unchanged preview digest.
Before its single template update, it saves private before snapshots, the full
payload and write intent, and acquires the permanent per-origin/target lock.
The update transports the exact unchanged bound workflow content because the
native update API can clear a graph when that binding is omitted. It never
calls a workflow-write endpoint, creates a template, publishes, or repeats a
migration-record callback.

Two stable readbacks must match the entire proposed bundle. Only independently
proved native audit normalization and typed reference display-name omission are
accepted. A lost write result permanently blocks replay. An acknowledged write
with a failed readback retains its receipt and lock for investigation; it is
never automatically replayed or rolled back. Changing an artifact directory
does not create another attempt.

Readback-only validation may append fresh typed organization evidence and two
stable snapshots to prove native display-name omission. It must verify the exact
original payload and preserve every original write report, receipt, intent and
permanent lock, including its historical failure status. Only workflow reader
display names may be omitted: root readers, ordered identities, types and all
other metadata remain protected. This validation cannot enter the write path,
clear a lock, or authorize another attempt.

Default tests use fake clients. Live operator artifacts and credentials must
stay outside version control; credentials come from environment variables.
