## 操作约定

使用 `$mk-migrate-server`。用户明确要求执行迁移时，该请求授权上述范围内的准备、校验、新建 `MK_TEST_` 草稿、工作流草稿、回读及工具既定迁移记录提交。检查通过后直接带 `--confirm-write` 执行，不再等待“确认写入”。只翻译、检查或预演的任务不写入。

已有兜底配置是本任务的既定处理策略，按对象类型主动使用，包括模版权限和符合条件的直接人员／岗位；主动传入必要开关，不逐个索要授权或要求补目标 fdId。用户明确限制优先。保留引擎的环境、身份、类型、可信 DSL 校验，不为兜底修改源数据或伪造审查。

每次执行前检查历史并保存计划和写入意图；失败后看实际报告判断副作用。未知写入不重放，已有目标不重复创建，不更换目录或迁移键绕过。发布、删除、更新已有模板、锁定草稿/已发布表单修复和回调补写不包含在普通迁移授权中。

只通过 `mk-migrate-secure run --` 操作引擎；不读取加密源码、不打印凭据、不自动锁定/解锁或改系统权限。同一阻塞只报告一次，无新状态不重复等待消息。

## 完成记录

按实际结果填写：源流程、创建 fdId、模板状态、回读、迁移记录、兜底与 warning、未完成项及证据路径。未完成或结果不明不能标记为成功。
